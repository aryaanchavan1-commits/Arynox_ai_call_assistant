# Phase 0 Evidence and Direct Agent Gateway Decision

Date: 2026-07-19

Qualified device: Xiaomi POCO M2 Pro (`gram`, Qualcomm `atoll`)

Software: Android 15 / API 35, LineageOS `lineage_miatoll`, Magisk 30.7, SELinux Enforcing

## Executive decision

The hardware feasibility gate for a direct cellular-audio gateway has passed in both directions on this exact device and ROM:

- PCM generated by Android reached the remote cellular party through the digital Telephony TX path.
- PCM from the remote cellular party was captured through the digital Telephony RX path.
- A bounded captured WAV was exported and audibly verified by the user.
- Both directions returned to an inactive, normal audio state after the call.

The project should therefore evolve from its previous SIP/Asterisk design into a **USB-only agent-to-phone cellular gateway**. SIP, RTP, Asterisk, Wi-Fi, and LAN control/media transports are outside the target product. The PC application is the sole bridge between the Android phone and agents such as Hermes or OpenClaw.

This is an evolution of the existing repository, not a rewrite from scratch.

## Exact conclusion and remaining qualification

### Proven

This device/ROM supports **directional digital cellular audio**:

1. Android PCM -> Telephony TX -> remote cellular party.
2. Remote cellular party -> Telephony RX -> Android PCM.

There was no acoustic speaker-to-microphone dependency in either proven route.

### Not yet proven

The two directions were qualified independently. The following remain implementation and acceptance gates:

- simultaneous continuous full-duplex streaming;
- bounded end-to-end transport latency and jitter;
- backpressure behavior under a slow or disconnected agent;
- echo/double-talk behavior during simultaneous speech;
- repeated-call and long-call soak;
- screen-off/Doze behavior;
- USB disconnect/reconnect and ADB-forward recovery;
- process death and phone reboot recovery;
- safe agent-driven dialing/answering/hangup under policy controls.

The accurate milestone is therefore:

> Directional digital-audio proof is complete. Production full-duplex gateway qualification is the next phase.

## Target architecture

```text
Hermes / OpenClaw / other MCP-capable agent
    |
    | local MCP tools/resources
    v
PC Gateway Application (`gatewayd` + MCP server)
    |
    | USB debugging only
    | `adb forward tcp:<host-port> tcp:<phone-port>`
    | localhost socket: ordered control/events + binary PCM
    v
Android Gateway App (privileged, exact-device profile)
    |-- TelecomAdapter: dial, ring, answer, reject, hangup, DTMF
    |-- CallSession: serialized state machine and idempotent teardown
    |-- AudioBridge: Telephony RX capture + Telephony TX injection
    |-- DeviceAudioPlugin: exact `gram`/`atoll` capability contract
    |-- GatewayTransport: commands, events, media, heartbeat/backpressure
    v
Cellular modem / SIM / remote party
```

### USB-only transport invariant

- Android listens only on its loopback interface.
- The PC application owns `adb forward tcp:<host-port> tcp:<phone-port>` and verifies the expected device serial/fingerprint before connecting.
- ADB establishes the USB tunnel; ADB shell commands are not used to carry PCM or remotely execute arbitrary commands.
- The forwarded localhost socket carries ordered control/events and full-duplex binary PCM.
- There is no phone LAN listener, Wi-Fi mode, WSS endpoint, SIP registration, RTP session, STUN, or Asterisk dependency.
- On USB loss, injection stops immediately, capture buffers are zeroized, and the configured call policy decides whether to preserve or end the cellular call.

### Protocol split

- **MCP:** the only agent-facing API, exposed locally by the PC application. Tools include `phone.status`, `phone.dial`, `phone.answer`, `phone.reject`, `phone.hangup`, and `phone.send_dtmf`; resources expose capabilities, session state, and privacy-safe metrics.
- **USB media socket:** ordered call events and real-time binary PCM over the ADB-forwarded localhost connection. Raw audio must not pass through ordinary MCP calls.

Suggested PCM framing for the first full-duplex slice:

- PCM16 little-endian, mono, 16 kHz.
- 20 ms frames: 320 samples / 640 bytes.
- Header fields: protocol version, stream direction, session ID, sequence number, monotonic timestamp, payload length, flags.
- Bounded queues; never unbounded buffering.
- Sequence-gap, overrun, underrun, and latency metrics.
- Explicit behavior when transport is lost: stop injection immediately, stop/zeroize capture buffers, preserve or end the cellular call according to configured policy.

## Reuse map

- `app/.../gsm/GsmCallService.kt`: retain InCallService integration.
- `app/.../gsm/GsmCallManager.kt`: retain Telecom callbacks and call-control primitives, but remove SIP/audio-mixer coupling.
- `app/.../service/GatewayService.kt`: retain foreground lifecycle, notification, boot, and wake handling; replace SIP registration/reconnect with USB-session state.
- `app/.../MainActivity.kt` and resources: retain useful dialer/status/settings UI; replace SIP credentials with USB status, permissions, and safety-policy controls.
- `app/.../DeviceSelector.kt` and tests: retain exact device selection.
- `probe/.../MainActivity.kt`: promote the proven Telephony TX construction/routing logic into production `AudioBridge` code.
- `downlinkProbe/.../MainActivity.kt`: promote the proven `VOICE_DOWNLINK`/Telephony RX logic into production `AudioBridge` code.
- `tools/diag`: retain privacy-safe device qualification and restoration diagnostics.

### Remove from the target product

- `app/.../sip/*`
- `app/.../rtp/*`
- `app/.../net/StunClient.kt`

These legacy SIP/RTP/STUN components are not part of the USB/MCP architecture. Preserve their history in Git, but remove them from the production build and runtime rather than maintaining an optional adapter.

### Replace, do not reuse

- `app/.../bridge/CallOrchestrator.kt`: it is structurally coupled to SIP/RTP and acoustic/shared-hardware assumptions. Replace it with a transport-neutral `CallSession` state machine.
- Legacy production `magisk/`: do not ship it forward. It contains global audio-concurrency properties, boot scripts, broad privileges, and a PermissionController replacement. The production module must be rebuilt from the narrow proven permission model and audited independently.

## Production component boundaries

### Android

- `TelecomAdapter`
  - Emits sanitized call-state events.
  - Performs typed dial/answer/reject/hangup/DTMF operations.
  - Never accepts shell commands or arbitrary intents from the network.

- `CallSession`
  - One serialized actor/state machine for the active call.
  - States such as `IDLE`, `RINGING`, `DIALING`, `ACTIVE_NO_MEDIA`, `STREAMING`, `TEARING_DOWN`, `ERROR`.
  - Idempotency keys for all mutating commands.
  - Single teardown path for remote hangup, local hangup, transport loss, process stop, and errors.

- `AudioBridge`
  - Captures only `VOICE_DOWNLINK` and requires actual `TYPE_TELEPHONY`.
  - Injects only via the proven media/Telephony TX route and requires actual `TYPE_TELEPHONY`.
  - Uses fixed pools/bounded buffers and zeroizes released PCM.
  - Does not persist audio on the phone. The Linux gateway records the two directional streams under the enforced consent/retention policy.

- `DeviceAudioPlugin`
  - Exact `gram`/`atoll` fingerprint and capability match.
  - Unknown builds fail closed.
  - No guessed mixer writes; the qualified path required no manual mixer toggles.

- `GatewayTransport`
  - One authenticated controller.
  - Binary PCM and ordered JSON/control events.
  - Heartbeats, bounded queues, metrics, and explicit disconnect policy.

### PC

- `gatewayd` (Linux only)
  - Owns ADB device selection, port forwarding, USB health, and reconnect.
  - Converts device events/media into stable local APIs.
  - Streams PCM directly to/from a pluggable realtime voice-provider adapter; ElevenLabs is the first provider target.
  - Owns high-level policy, audit, mandatory recording for agent-handled calls, consent, access, retention, export, and deletion.
  - Preserves the remote-person stream and exact agent-injection stream separately, plus a synchronized human-review artifact and timestamped transcript/event ledger.
  - Refuses to start agent media unless the recording policy is satisfied and both recording tracks are open; recording/storage failure triggers a configured fail-closed stop-or-human-transfer policy.

- MCP server
  - Thin semantic layer over `gatewayd`, not the PCM carrier.
  - Exposes safe incoming-call events and answer/reject controls, policy-gated outbound dial, hangup, DTMF, status, capabilities, provider configuration, transcripts, and recording/caller-context resources to Hermes, OpenClaw, and other MCP clients.
  - Every mutating tool requires an idempotency key and is enforced by `gatewayd`; MCP cannot bypass consent, destination, duration, rate, recording, or device-identity policy.
  - Starts/stops agent sessions, selects provider/voice/agent configuration, supports bounded `phone.speak` text injection, and publishes transcripts/events/status.

- Caller memory store (Linux only)
  - Resolves repeat callers through a salted identifier derived from normalized E.164; full numbers remain separately protected and are not exposed as agent-facing identity.
  - Supplies a bounded context containing approved summary, language/voice preferences, durable facts, and open follow-ups only when memory consent is valid.
  - Never injects raw call history by default. Post-call agent proposals are validated and audited; speech cannot modify consent, allowlists, trusted identity, or call policy.
  - Supports authorized review, correction, retention expiry, export, and deletion.

- Realtime agent integration
  - Audio never traverses ordinary MCP messages; the Linux gateway connects the USB PCM stream directly to the provider streaming API for low latency.
  - ElevenLabs ordinary TTS supports one-way `phone.speak`; full dialogue requires ElevenLabs Conversational AI or another realtime STT+LLM+TTS adapter.
  - Provider adapters remain PC-side and consume the same `gatewayd` audio source/sink API, so the phone protocol is vendor-neutral.

## Agent call-control safety gates

The target supports agent-made calls, but outbound autonomy must not be enabled merely because `CALL_PHONE` works.

Before unrestricted agent dialing, require:

- authenticated device enrollment and one active controller lease;
- E.164 normalization;
- destination allowlist/denylist;
- premium, emergency, and international restrictions;
- per-call confirmation mode for early development;
- rate, duration, daily spend, and per-destination cooldown limits;
- idempotency keys to prevent duplicate calls;
- explicit inbound-only and media-only kill switches;
- clear on-device active-call indicator and physical stop control;
- redacted audit records (do not store full phone numbers by default);
- agent-handled calls require an explicit consent/recording policy; the agent media session fails closed if compliant recording cannot start or remain complete;
- recordings require authenticated human-review access, immutable hashes/manifests, retention expiry, audited export/playback/deletion, and legal-policy configuration appropriate to the deployment jurisdiction.

Initial development should keep dialing manually approved or allowlist-only. Automatic dialing can be enabled only after the policy tests pass.

## Permission and Magisk direction

Do not copy the current broad manifest/allowlist blindly. Derive the production set from the exact features:

- `RECORD_AUDIO` as a visible runtime permission.
- `CAPTURE_AUDIO_OUTPUT` for proven downlink capture.
- `MODIFY_AUDIO_ROUTING` and `MODIFY_PHONE_STATE` only for the proven Telephony TX path and typed call/audio operations that demonstrably require them.
- Ordinary call-control/foreground/network permissions only where the selected Telecom architecture requires them.
- No call-log, phone-number, location, shared-storage, global app-op, PermissionController replacement, SELinux weakening, or global audio-property behavior without a separately demonstrated requirement and approval.

Every changed privileged artifact requires tests, lint, manifest/allowlist audit, exact hashes, explicit approval, reboot verification, and rollback instructions.

## Delivery plan

### Phase 1 — USB core, no autonomous calling

1. Add pure, JVM-tested protocol framing, session reducer, idempotency, and bounded queue logic.
2. Extract the proven Telephony RX/TX implementations into a production `AudioBridge` behind interfaces.
3. Add `gram`/`atoll` capability profile marked `directional-proof`; unknown builds fail closed.
4. Implement an Android loopback media/control server and a PC USB client through `adb forward`.
5. Stream synthetic PCM full duplex during a manually established consenting call.
6. Measure route, loss, jitter, underruns, latency, and restoration.

Acceptance: simultaneous two-way PCM for at least five minutes, no acoustic fallback, no unbounded queues, clean hangup and transport-loss restoration.

### Phase 2 — call session and safe remote controls

1. Replace the legacy SIP orchestrator with the pure `CallSession` actor.
2. Expose status, answer, reject, hangup, and DTMF over typed authenticated commands.
3. Add outbound dialing behind manual confirmation and destination allowlist.
4. Add process-death/reboot recovery tests and repeated-call tests.

Acceptance: idempotent commands, duplicate-dial prevention, deterministic teardown, and no call control outside policy.

### Phase 3 — agent runtime

1. Add PC `gatewayd` audio source/sink APIs.
2. Connect pluggable low-latency STT/TTS or a realtime voice-agent provider, with local Supertonic TTS and ElevenLabs evaluated as initial adapters.
3. Add a thin MCP server for semantic tools and status resources.
4. Keep audio on direct provider/USB streams; MCP carries commands, transcripts, and events only.
5. Add synchronized dual-track recording, a mixed review artifact, transcript/event manifests, hashes, retention/access/deletion controls, and fail-closed recorder health.
6. Add barge-in, VAD, interruption, latency, and consent controls.

Acceptance: one controlled end-to-end AI call with consent, policy enforcement, intelligible bidirectional audio, and measured latency.

### Phase 4 — USB soak and appliance hardening

1. Run USB unplug/replug, ADB restart, screen-off, Doze, repeated-call, and long-call soak.
2. Add deterministic PC-app and phone-app process-death recovery.
3. Package the PC application and local MCP server with one-command device discovery/forwarding.
4. Publish the exact supported fingerprint/capability matrix and rollback guide.

## Approval gate

Approval of this document authorizes architecture refactoring and development work, but does not authorize:

- installing a new privileged APK/Magisk artifact without its own hash review;
- dialing a real destination without the configured consent/policy gate;
- recording or retaining call audio by default;
- weakening SELinux, modifying PermissionController, or applying global audio properties.

Recommended decision:

> Approve Phase 1: refactor the existing repository into a USB-debugging-only PC/phone gateway, reuse the proven Telecom and Telephony RX/TX paths, remove SIP/RTP/Asterisk/STUN and LAN transport from the target product, expose control to Hermes/OpenClaw through a local PC MCP server, and require a new audited install gate before device deployment.
